# PRISM v0.69 / Phase 1B.4 — Canonical Advisory Tally Receipts

## Status and boundary

Offline, isolated governance research only. This module does NOT implement a DAO,
production voting, a validator quorum certificate, a closed election, finality,
consensus authorization, treasury spending, timelock execution, on-chain
admission, or a distributed/complete ballot ledger. No change to v0.61 execution
or v0.68 finality is made.

Phase 1B.3 already validates an eligibility roster, requires a separately
trusted SHA-256 snapshot pin, verifies votes, rejects duplicates/ineligible
voters, and computes weight/quorum/approval with exact integer arithmetic.
Phase 1B.4 adds a canonical ballot-set digest and an unsigned, reproducible
**observation receipt** bound to every input and derived tally field.

## Public APIs

- `AdvisoryBallotSetCommitment([]SignedAdvisoryVote)` hashes ballots sorted by
  canonical lowercase voter public key (input order does not matter). It binds
  every vote commitment and all 64 signature bytes; duplicates are rejected by
  public key regardless of choice or nonce. `nil`/empty sets are allowed. This
  function checks shape, NOT Ed25519 authenticity or electorate eligibility.
- `BuildAdvisoryTallyReceipt(snapshot, trustedSnapshotSHA256,
  trustedBallotSetSHA256, proposal, trustedContext, ballots)` calls the already
  existing full Phase 1B.3 tally verification, checks an *independently trusted*
  ballot-set hash pin, then emits an unsigned, domain-separated SHA-256 receipt.
  A failure returns an empty receipt and error: NO partial tally.
- `VerifyAdvisoryTallyReceipt(receipt, snapshot, trustedSnapshotSHA256,
  trustedBallotSetSHA256, proposal, trustedContext, ballots)` recomputes the
  entire object, not merely the hash string, and fails closed if any byte or
  tally component is different. The verifier needs the source votes.

All hashes use explicit binary fields, length prefixes where strings are
involved, fixed 8-byte big-endian unsigned integers, distinct domain strings,
and single-byte 0/1 booleans. The receipt includes protocol version,
network/chain/genesis, proposal, snapshot and ballot-set digests, observed
height, policy threshold bps, counts, weights and outcomes.

## Critical limits

The roster **and** ballot-set SHA-256 values must be pinned through a distinct,
independently authorized and auditable process. A SHA-256 value generated by
an untrusted vote collector and subsequently passed back to this API does not
make that collector trustworthy. A perfectly valid receipt may still describe
an incomplete or selectively withheld ballot set. There is no durable
reconciliation with `AdvisoryVoteReplayStore`, no signed attestation by a
trusted elections authority, no global cross-node ordering, and no voting
close/freeze mechanism. `ObservedAtHeight` is not a closure height and can be
inside the proposal voting window; results can therefore change as new votes
arrive. The caller must supply a trusted chain height, which is not proven here.

The `AdvisoryPassed` flag is a *non-binding mathematical observation*, not a
permission to submit any proposal, execute a timelock or release funds.

## Offline checks

Execute from the PRISM v0.69 worktree with a private `umask 077` (required by
pre-existing Linux replay-store permission tests):

```bash
umask 077
export PATH="/usr/local/go/bin:$PATH"
export GOTOOLCHAIN=local GOPROXY=off GOSUMDB=off GOWORK=off

go test -count=1 ./internal/governancev069
go test -race -count=1 ./internal/governancev069
go vet ./internal/governancev069
```

Regression tests cover canonical order independence, fixed test vectors,
separate hash domains, forgery/tally tampering, network/height/proposal pinning,
roster mutation, ballot omission, changed choice/nonce, ineligible/duplicate
voters, unsigned empty elections and weights near `math.MaxUint64`.

## Next hardening steps (not shipped)

1. Independently verified snapshot/ballot-set authority and authenticated,
   deterministic collection/freeze policy.
2. Reconciliation of persisted ballot admissions and full data availability.
3. Adversarial multi-node audit with a signed, authority-reviewed finalization
   protocol before discussing any production consensus integration.
